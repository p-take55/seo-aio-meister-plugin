# 記事の概要を作って渡す

概要は、書き手が迷わずに書けるだけの材料を渡すためのもの。ここでは本文を書かない。本文は `article-writing` で書く。

## A. 新しい記事の概要

### 1. 最終的に選ぶ

書く問いを人間が既に承認していれば、選び直さない。次の 3 つがそろっているかだけを確かめ、欠けていれば書く前に報告する。

承認がまだなら、`keyword-evidence` と `ai-citation-check` の結果から、依頼された数だけ選ぶ。次の 3 つがそろわない問いは選ばない。

- 戦略のテーマに入っている
- 勝てる理由を、事業の概要から引ける
- 競争の判断が「難しい」ではない

そろう問いが足りなければ、数を減らして報告する。無理に埋めない。

### 2. 上位と引用元を読む

「現状」と「抜けている論点」は、読まないと書けない。候補の文書にある上位のページと、AI による概要の引用元を、ここで開いて読む。開けなかったページ（URL が分からないものなど）は、開けなかったと書く。

### 3. 概要を書く

```markdown
## 〈キーワード〉

- 短い名前: 〈英数字とハイフン。概要と原稿のファイル名、作業ブランチの名前に使う〉
- 種類: 新規
- 問い: 〈読者が実際に投げる言い方〉
- テーマ: 〈戦略のどのテーマか。柱の記事か、関連の記事か〉
- 読者と段階: 〈誰が、知る・比べる・決めるのどこで〉
- 検索数と推移: 〈値。データ源と確認日〉
- 現状: 〈上位と AI の引用の様子。見た URL〉
- 勝てる理由: 〈記事に入れるべき自社だけの根拠〉
- 抜けている論点: 〈上位が書いていないこと〉
- つなぐ記事: 〈同じテーマの既存の記事。互いにリンクする相手〉
- 注意: 〈事実確認が要る点、書いてはいけないこと〉
- 読んだ出どころ: 〈開いて読んだページの URL と題。開けなかったものは、その旨〉
- 原稿の場所: 〈書いたら足す。ブランチと PR、または文書〉
```

## B. 書き直す記事の概要

`seo-results-review` で「あと一歩」「別の問いで出ている」とされた記事に使う。

### 1. 今の記事と上位を読む

記事の本文、その記事が表示されている問い（Search Console があれば）、狙った問いの今の上位と AI の引用（`ai-citation-check`）を読む。

### 2. 概要を書く

```markdown
## 〈記事のタイトル〉（〈URL またはファイル〉）

- 種類: 書き直し
- 狙う問い: 〈変えないなら元のまま。変えるなら新旧と理由〉
- 今の結果: 〈表示回数、順位、引用の有無。期間とデータ源〉
- 直す理由: 〈1 つに絞る。例: 上位にある論点が無い、冒頭で答えていない、数字が古い〉
- 足すもの: 〈論点、自社の根拠、表や手順〉
- 削る・直すもの: 〈古い記述、問いからそれた節〉
- 変えないもの: 〈URL、効いている節〉
- 注意: 〈事実確認が要る点〉
```

直す点は 3 つまでにする。全部を書き換える概要は、新しい記事として A で作る。

## 渡す

概要は、渡し方にかかわらず、まず Project 文書 `docs/briefs/〈短い名前〉.md` に保存する（1 本に 1 つ。名前は英数字とハイフン）。受け入れの確認で、ここを読む。

そのうえで、`docs/seo-settings.md` の「記事を書く担い手」に従って渡す。

- **自分** → 続けて `article-writing` で原稿を書く。書いたら、その Session では受け入れ確認をしない。
- **Workflow** → 概要ごとに起動する。入力の項目名はその Workflow の定義に合わせ、概要の本文か文書の場所を渡す。操作は `aachat/contracts/workflow.md` に従う。
- **書き手の Agent** → 概要の文書の場所を添えて依頼する。
- **人間** → 返答で、概要の文書の場所を伝える。

最初に書く記事を人間がまだ承認していないときは、渡す前に Ask で確かめる。問いごとに、何の話か（製品や媒体の名前が変わっていれば新旧の両方）を書き、外す単位を選べる選択肢にする。

## 記録する

Project 文書 `docs/seo-log.md` に追記する。

- 概要ごとに、日付・種類・問い・テーマ・概要の文書の場所（1 行）
- 起動した Run の ID（あれば）
- 候補から外した主な問いと理由（次回、同じ検討を繰り返さないため）
- 戦略の見直しにつながる気づき（あれば）

Project のデータベースが使えるときは、その問いの状態を `briefed` に直す（`seo-database` の 3）。

`docs/keyword-candidates.md` の、その問いの行の「状態」を「概要あり」に直す。文書が古い形で「状態」の欄が無ければ、`keyword-evidence` の「候補の文書に残す」の形に直してから書く。

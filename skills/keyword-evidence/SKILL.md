# 検索数と推移の根拠を取る

根拠は 2 種類ある。分かることが違うので、設定されていれば両方取る。

| 種類 | データ源 | 分かること |
|---|---|---|
| 1. 自社の実数 | Search Console（無料） | 自社サイトが表示された問いの回数と順位。まだ表示されていない問いは出ない |
| 2. 世の中の検索数 | ラッコキーワード・DataForSEO・Ahrefs のどれか 1 つ | どの問いでも、月間の検索数と推移。長い問いは 0 やデータなしになりやすい |

## 手順

1. `seo-data-sources` で、使えるデータ源を決める。
2. Search Console が使えれば、まずそれで候補を引く（`../seo-data-sources/providers/search-console.md`）。
3. 検索数のツールを 1 つ選び、候補をまとめて 1 回で送る。
4. 使えるものが無いとき、または数字が出なかった問いは、下の「推測」で補う。
5. Project のデータベースが使えるときは、取った出力をその場でデータベースに入れる（`seo-database` の 2。語とテーマの対応を付ける）。取った数字を、一時置き場だけに残さない。

エラーで取れなかったときは、次のデータ源に進み、起きたことを報告に書く。鍵や残高は自分では直せない。

## 読み方

- **推移**: 直近が平均の 1.3 倍以上なら「伸びている」、0.7 倍以下なら「減っている」、その間は「横ばい」。元の数字が小さすぎるときは「不明」。
- **0 やデータなしは、落とす理由にしない。** AI に投げられるような長い問いは、検索されていても 0 と出る。推測で補う。
- **Search Console の表示回数は検索数ではない。** 自社が出た回数で、順位が低いと実際の需要より小さく出る。別の項目として書く。
- **伸ばせる問い**: Search Console で表示が多く、順位が 8〜30 位の問いは、候補に加える。

## 買う気の強さを読む

検索数は「何人が探しているか」で、「その人が買いそうか」は分からない。検索広告のクリック単価で補う。

- **クリック単価が高い問いは、買う気が強い。** 広告主がお金を払ってでも取りたい検索で、導入や購入に近い人が多い。検索数が小さくても候補に残し、順を上げる材料にする。
- **同じテーマの中で比べる。** 単価の水準は業界で違う。絶対額ではなく、同じテーマの候補どうしで高い・低いを見る。
- **「会社」「ツール」「比較」「料金」が付く問いは高くなりやすい。** 同じ語の「とは」「対策」と並べると、差が見える。同じ対象についての問いどうしでも、手順を調べる言い方より、導入を決める側の言い方のほうが高く出やすい。
- **空欄や低い単価は、落とす理由にしない。** 「〜とは」のような調べる問いは単価が付きにくいが、AI に引用される入口になる。買う気の強い問いと調べる問いを、混ぜて選ぶ。
- **広告の競合（LOW / MEDIUM / HIGH）は、記事の順位の取りやすさではない。** 広告を出している会社の多さで、その分野にお金が動いているかの目安として読む。

単価が出るのは DataForSEO だけ（検索数と同じ 1 回の呼び出しで返り、追加の料金は無い）。ほかのツールを使っているとき、または値が返らないときは「データなし」と書き、推測で埋めない。その場合、並べる基準からこの項目を外し、外したことを報告に書く。単位はドルなので、ほかの通貨で伝えるときは為替の値と日付を添える。

## 推測（数字が取れないとき）

- Google のサジェストに出るか、何文字目で出るか
- 検索結果に、その問いに正面から答える記事がどれだけあるか
- Google トレンドでの動き（見られる範囲で）

「多い・中くらい・少ない」の 3 段階で書き、推測だと明記する。数字を作らない。

## 候補の文書に残す

**データベースを使っている Project** では、全部の語はデータベースにある。`docs/keyword-candidates.md` には、おすすめする問いと、その根拠・勝てる理由だけを書き、「全部の語はデータベースにある」と 1 行添える。下の表は、おすすめの問いの行だけでよい。

**データベースを使っていない Project** では、取った結果を Project 文書 `docs/keyword-candidates.md` に全部残す。取り直さずに済むように、選ばなかった候補も消さない。次に調べたときは、同じ問いの行を新しい値で書き換え、確認日を直す。

```markdown
# キーワードの候補

確認日: YYYY-MM-DD ／ データ源: 〈使ったもの〉 ／ 国と言語: 〈値〉

| 問い（検索の言い方） | テーマ | 検索数 | 直近 3 か月 | 推移 | クリック単価 | 広告の競合 | AI による概要 | 自社の引用 | 自社の表示と順位 | 状態 | 順 | 勝てる理由 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
```

- **テーマは全部の行に書く。** 戦略のどのテーマの候補として広げたかは、広げた時点で分かっている。あとで分からなくなる前に書く。どのテーマにも入らない語は、その行を残さない。
- **状態**は「候補・提案中・承認済み・概要あり・原稿あり・確認済み（公開待ち）・公開済み・見送り」のどれか。見送りは理由を「勝てる理由」の欄に書く。
- **順**は、今回おすすめする問いにだけ 1 から付ける。
- 「AI による概要」と「自社の引用」は、`ai-citation-check` で確かめた問いにだけ「あり・なし」を書く。確かめていない問いは「未確認」。

## 記録の形

| 項目 | 内容 |
|---|---|
| 検索数 | ツールの数値、または 3 段階の推測 |
| 自社の表示 | Search Console の表示回数と順位（期間つき）。無ければ「データなし」 |
| 推移 | 伸びている・横ばい・減っている・不明 |
| 買う気の目安 | クリック単価と入札の目安（ドル）、広告の競合。同じテーマの中で高い・ふつう・低い。無ければ「データなし」 |
| データ源 | 使ったものをすべて（例: Search Console、ラッコキーワード） |
| 確認日 | YYYY-MM-DD |

# キーワード戦略を作る

前提: 事業の概要がある。無ければ先に `seo-business-research` を行う。

## 1. テーマの候補を出す

顧客の困りごと × 自社だけの根拠、が重なる領域をテーマにする。5〜8 本出す。

## 2. テーマごとに確かめる

- **需要**: 代表的な問いを 3 つ挙げ、`keyword-evidence` で検索の有無を見る。この skill が無いときは、検索のサジェストに出るかと、検索結果にその問いに答える記事があるかで見当を付け、推測だと書く。
- **競争**: 代表的な問い 1〜2 つを `ai-citation-check` で見る。この skill が無いときは、Web 検索で上位を読む。上位と AI の引用を、大手メディアや公式が埋めているか、個人の記事や古い記事が残っているか。
- **勝てる理由**: 事業の概要の「自社だけの根拠」のどれを使うか。
- **事業への近さ**: 読んだ人が製品を検討する段階にどれだけ近いか。

## 3. 絞る

狙うテーマを 3〜5 本にする。新しいサイトや記事の少ないサイトでは、範囲が狭く具体的な問いが多いテーマを先に置く。広い語で大手と正面から競うテーマは後に回すか、避ける。

## 4. テーマごとに記事の組み方を決める

テーマは、柱の記事 1 本と、関連の記事 5〜10 本の組にする。

- **柱の記事**: テーマ全体の問いに答える。関連の記事すべてにリンクする。
- **関連の記事**: 狭く具体的な問い 1 つに答える。柱の記事と、近い関連の記事にリンクする。

新しいサイトでは、関連の記事を 3〜4 本出してから柱の記事を書く。先に狭い問いで表示を得るほうが早い。

## 5. 文書にする

Project 文書 `docs/keyword-strategy.md` に書く。

```markdown
# キーワード戦略

状態: 承認待ち / 承認済み（YYYY-MM-DD、承認者）

## 狙うテーマ

### 1. 〈テーマ名〉
- 読者と段階: 〈誰が、知る・比べる・決めるのどこで〉
- 勝てる理由: 〈自社だけの根拠。事業の概要の該当箇所〉
- 代表的な問い: 〈3 つ〉
- 柱の記事: 〈テーマ全体に答える 1 本。問いと、置く場所〉
- 関連の記事: 〈柱から枝分かれする、狭い問いの候補 5〜10 個〉
- 競争の現状: 〈上位と AI の引用の様子。確認日〉
- 優先度: 〈高・中・低と、その理由〉

## 避けるテーマ
- 〈テーマ〉: 〈理由〉

## 見直す条件
- 〈例: 記事が 20 本公開された、新製品が出た、3 か月たった〉
```

## 6. 承認を得る

Ask で、狙うテーマと避けるテーマの一覧を見せ、承認か修正を求める。承認されたら状態を「承認済み」にし、日付と承認者を書く。承認前の戦略でキーワード選びを始めない。

## 見直し

公開した記事の結果（Search Console の数字など）が Project にあれば、どのテーマが効いたかを見て、優先度の変更を Ask で提案する。

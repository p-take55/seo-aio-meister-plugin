# 始める前に、そろっているかを確かめる

足りないものがあっても、できる範囲で仕事は始められる。ここでの目的は、何が無いために何ができないかを、最初にはっきりさせること。

確かめた結果は、Project 文書 `docs/seo-settings.md` に置く。ほかの skill は、サイトの URL や国の指定をここから読む。

## 1. サイトと、対象の国・言語

| 決めること | 確かめ方 | 無ければ |
|---|---|---|
| サイトの URL（`https://` から） | Project の説明、repo の設定、人間の依頼文 | Ask で聞く。推測しない |
| 自社のドメイン（引用の判定に使う。複数あれば全部） | サイトの URL と、転送先 | サイトの URL から決める |
| 対象の国と言語 | サイトの本文の言語、`<html lang>`、事業の商圏 | Ask で聞く |

国と言語は、データ源ごとに書き方が違う。決めたら、使うデータ源の値も一緒に書く。日本・日本語なら次のとおり。それ以外は `seo-data-sources` の各手順にある調べ方で決める。

| データ源 | 日本・日本語の値 |
|---|---|
| DataForSEO | `--location 2392 --language ja` |
| ラッコキーワード | `--location Japan --language Japanese` |
| Ahrefs | `country=jp` |
| Google のサジェスト | `hl=ja` |

対象の国と言語を決めないまま、検索数を取らない。別の国の数字で戦略を作ることになる。

## 2. Project の今の段階

| 見るもの | あれば | 無ければ |
|---|---|---|
| 事業の概要 `docs/business-profile.md` | 済み | `seo-business-research` から始める |
| サイトの受け皿 `docs/site-readiness.md` | 済み。「止める」が残っていないかを見る。記録には直ったとあるのに文書が「未」のままなら、`site-readiness-audit` で公開中のページを確かめ直し、文書を直す | `site-readiness-audit` を行う |
| キーワード戦略 `docs/keyword-strategy.md`（状態が承認済み） | 済み | `keyword-strategy` から始める |
| 記録 `docs/seo-log.md` | これまでに選んだ問いと結果が分かる | 初回として扱う |

文書に「承認待ち」とあっても、Ask が回答済みのことがある。文書に書かれた Ask の番号を直接読み、回答に合わせて文書を直してから進む。

## 3. サイトの repo

- Project の repository に、サイトの repo が設定されているか。作業フォルダにサイトのファイルがあるかで分かる。
- 記事の置き場所（例 `content/blog/`）と、記事の書式（先頭の項目、画像の置き場所）を見つける。
- 既存の記事の本数と、最も新しい公開日を数える。サイトのひな形に付いてきた見本の記事（別の言語、製品と無関係な題、ひな形の作者名）は、自社の記事に数えない。

repo が無い、または記事の置き場所が分からないときは、人間に聞く。

## 4. 記事を書く担い手

誰が記事を書くかを決める。決まっていなければ「自分」にする。

| 担い手 | いつ選ぶか | 書き方 |
|---|---|---|
| 自分（既定） | ほかに決まっていない | `article-writing` で書く。受け入れ確認は別の Session で行う |
| 記事作成の Workflow | Project に既にある（Workflow の一覧を見る。操作は `aachat/contracts/workflow.md`） | 概要を渡して起動する |
| 書き手の Agent | Project のメンバーにいる | 概要の場所を添えて依頼する |
| 人間 | 人間が自分で書くと言っている | 概要の場所を伝える |

あわせて、公開までの流れを確かめる（作業ブランチに置くだけか、PR を作るか、誰が確かめてマージするか）。分からなければ人間に聞く。決まるまでは、原稿を作業ブランチに置くところで止める。

書き手が自分以外のときは、次の 3 つを書き手に求める。

1. `docs/briefs/` の概要を 1 つ受け取り、その問いに答える記事を、サイトの記事の書式で書く。
2. 概要の「勝てる理由」と「注意」を守る。事業の概要に無い数字や実績を作らない。
3. 公開する前に、原稿（作業ブランチか PR）を `article-acceptance-check` に回す。

## 5. データ源

`seo-data-sources` の手順で、設定されているデータ源を確かめ、つながるかを 1 回ずつ試す（試し方は `seo-data-sources` の「つながるかを試す」）。何もつながっていなくても進められる。その場合、検索数は推測に、AI の引用は「未確認」になる。

足りないデータ源をつなぐのは `seo-data-connect` で行う。

あわせて、Project のデータベースが使えるかを確かめる。使えるなら、`seo-database` の 1 で表を用意する。検索数や引用元のような、たまっていく数字はそこに置く。使えない Project（権限が無いなど）では、これまでどおり文書に残す。どちらにしたかを、設定の文書に書く。

## 6. 設定の文書を書く

`docs/seo-settings.md` に書く。値が決まっていない項目は「未定」と書き、誰に聞いているか（Ask の番号）を添える。まだ聞いていなければ「未定（まだ聞いていない）」と書く。

```markdown
# SEO・AIO の設定

確認日: YYYY-MM-DD

- サイトの URL: 〈https://…〉
- 自社のドメイン: 〈example.com、…〉
- 対象の国と言語: 〈国、言語〉
  - DataForSEO: 〈--location … --language …〉
  - ラッコキーワード: 〈--location … --language …〉
  - Ahrefs: 〈country=…〉
  - Google のサジェスト: 〈hl=…〉
- 記事の置き場所: 〈repo のフォルダと、公開したときの URL の形。例 /blog/〈名前〉〉
- 記事を書く担い手: 〈自分／Workflow の名前／Agent の名前／人間〉
- 公開までの流れ: 〈例: 作業ブランチ → PR → 人間の確認〉
- 費用の上限: 〈人間に言われていれば〉
- 数字の置き場所: 〈Project のデータベース／文書（データベースが使えない理由）〉

## データ源

| データ源 | 状態 | 補足 | 確認日 |
|---|---|---|---|
| Search Console | 接続済み／依頼中／未接続 | 〈プロパティ、未接続の理由など〉 | YYYY-MM-DD |
| Google アナリティクス 4 | … | … | … |
| DataForSEO | … | … | … |
| ラッコキーワード | … | … | … |
| Ahrefs | … | … | … |
```

5 つとも行を書く。使わないと人間が決めたものは「未接続」とし、補足に理由を書く。

設定の文書が既にあって、この形と違うときは、値を保ったままこの形に直す。

## 6-2. 記録の文書

`docs/seo-log.md` が無ければ、次の 5 節で作る。各 skill は、自分の節に 1 行ずつ追記する。前の行を書き換えない。

記録が既にあって、節の分け方が違うときは、この 5 節に並べ直す。中身は消さない。当てはまる節が無い記録は、最後に「そのほか」の節を作って残す。

```markdown
# SEO・AIO の記録

## 選んだ問いと概要
| 日付 | 種類 | 問い | テーマ | 概要の場所 | 補足 |

## 受け入れの判断
| 日付 | 記事 | 判断 | 主な理由 | 戻した回数 |

## 公開した記事と結果の確認
| 日付 | 記事（URL） | 公開日 | 区分 | 主な数字 | 次の手 |

## データ源の接続
| 日付 | データ源 | 起きたこと |

## 使った額
| 日付 | データ源 | 何に | 額 | 残高 |
```

## 7. 報告する

返答に、次の表を載せる。

| 項目 | 状態 | 無いと何ができないか |
|---|---|---|
| サイトの URL と、対象の国・言語 | 決まった／未定 | 検索数と引用を、正しい国で取れない |
| 事業の概要 | あり／なし | 戦略を作れない |
| 承認済みの戦略 | あり／なし | 問いを選べない |
| サイトの repo と記事の置き場所 | あり／なし | 既存の記事との重なりを確かめられない |
| 記事を書く担い手と、公開までの流れ | 〈自分・名前〉／流れが未定 | 原稿を公開まで進められない |
| Search Console | つながる／未設定／エラー | 自社の実数と、公開後の結果が取れない |
| Google アナリティクス 4 | つながる／未設定／エラー | 記事が問い合わせや申し込みにつながったか、AI のサービスから人が来たかが分からない |
| 検索数のツール | 〈名前〉／未設定 | 検索数が推測になる |
| AI による概要のデータ | 〈名前〉／未設定 | 問いごとの引用が「未確認」になる |

その後、今の段階から仕事を始める。準備がすべてそろうのを待たない。
